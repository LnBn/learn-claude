# Practice Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `/review` brings every miss back at growing intervals as a new variant, and `/drill` runs mixed, unlabelled problems where the learner names the technique and then solves it.

**Architecture:** `hooks/practice.py` scans what already exists (quiz blocks in notes, graded exam schemes, finished interview rounds, drill results) and keeps cards in `<vault>/practice/.cards.json`; it schedules them, plans drills from the technique notes' records, validates drill problem files and records results. `technique.py` reads drill results for its notes and index; `lesson.py summary` reports due cards. Two skills, `review` and `drill`, drive it.

**Tech Stack:** Python 3.10+, standard library only; tests with `unittest` through `tests/_vault.py`.

**Spec:** `docs/superpowers/specs/2026-10-24-practice-design.md`

## Global Constraints

- Paths: `<vault>/practice/.cards.json`; `<vault>/practice/.drills/<id>.json` and `<id>.problems.json`; notes `<vault>/practice/YYYY-MM-DD.md`.
- `INTERVALS = [1, 3, 7, 16, 35]`; right → step + 1, retired past the last, else due `today + INTERVALS[step]`; wrong → step 0, due tomorrow; due when `due <= today` and active.
- First scan (no cards file): due `today + 1 + floor(k × 14 / N)`, k-th of N oldest first. Later: due `max(missed + 1, today)`.
- Keys: `quiz:<stem>#<anchor>#<sha1(title)[:8]>`, `exam:<paper stem>#<qid>`, `interview:<round stem>#p<i>`, `drill:<id>#<slot>`. A key once seen is never re-added.
- Scan exclusions: `.claude/`, `.obsidian/`, `techniques/`, `practice/`, any `exams/` or `interviews/` folder, fenced code. Review notes are scanned.
- Card ids `c1, c2, …` in creation order.
- Drill: default 8 slots; refuse under 4 technique notes with `a drill needs at least 4 technique notes; /techniques backfill makes them`; weight `1 + 2(1 − pass) + 2(1 − recognised)`, missing rate = 0.5; ≥ 2 slots from the top half by pass rate; seeded by the drill id; id `<YYYY-MM-DD>-<k>`.
- Output lines: `due` prints per card `<id> · <kind> · <label> — [[<source>|<label>]]`, `  techniques: …`, `  prompt: …`, `  key idea: …`; `drill-summary` prints `Recognised <k>/<n> · solved <k>/<n>` then `took <picked> for <technique>` per confusion; `stats` prints `active <a> · retired <r> · due today <d>` then `next 7 days: <d1> <d2> … <d7>`.
- Technique note line: `**Drills:** recognised <k>/<n> · solved <k>/<n>` directly after the `**Record:**` line; index column `Recognised` after `✗`.
- Brief line: `REVIEW DUE: <k> cards — /review asks them`.
- Reuse, do not duplicate: `technique.fenced`, `technique.note_sections`, `technique.anchor_of`, `technique.long_label`, `technique.load_techniques`, `technique.resolver`, `technique.collect`/`record`, `quiz_block.is_quiz_header`/`parse`, `answer_check`.
- Standard library only; match `technique.py`/`interview.py`. README is a tutorial.

## Review Focus

1. **A day boundary inside a session** (a review started at 23:55, answered at 00:05): scheduling uses the date of the `result` call, consistently. Test in Task 1 by recording on a fixed card and checking `due` arithmetic from `date.today()`.
2. **A quiz block whose title contains `#`, `|` or LaTeX**: the key is stable (hash of the title), the prompt is kept whole. Test in Task 1.
3. **The cards file missing after a first scan was done** (deleted by hand): the next scan treats it as first and spreads again — acceptable; but a corrupt (unparseable) cards file must not be overwritten silently. Test in Task 1: a corrupt file → scan refuses with a message.
4. **A drill with more slots than techniques** (n = 8, 5 notes): techniques repeat, every slot still has three distinct wrong options that are not its own technique. Test in Task 2.
5. **`drill-result` for a slot of a drill that does not exist, or an unknown card id for `result`**: refused with a message, nothing written. Tests in Tasks 1 and 2.
