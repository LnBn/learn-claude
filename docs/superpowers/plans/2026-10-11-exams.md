# Exams Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `/exam` sets a written exam paper on a course chapter or a lesson note, `/exam submit` grades it into the paper with feedback, and weak spots feed back into course progress and recall checks.

**Architecture:** A new skill (`skills/exam/SKILL.md`) holds the procedure; the teacher writes the paper and its JSON marking scheme with the Write tool. A new script (`hooks/exam.py`) does everything that must be exact: paths, validation, parsing the filled-in paper, multiple-choice grading, inserting feedback, totals, course state. Small changes to `md_log.py` (muting), `book.py` (state, index, chapter-complete line), `lesson.py` (`EXAM MISSES`) and `figures.py` (papers in `exams/`) connect it to what exists.

**Tech Stack:** Python 3.12 standard library only (the repo installs nothing for its scripts). Tests use `unittest`, run with `python3 -m unittest discover -s tests -v` (pytest is not installed).

**Spec:** `docs/superpowers/specs/2026-10-11-exams-design.md`

## Global Constraints

- Standard library only, in scripts and in tests.
- Scripts are invoked as `python3 .claude/hooks/<script>.py …` from the vault root; the repo is installed as `<vault>/.claude/`. Tests reproduce that layout in a temp dir.
- Papers: `courses/<slug>/exams/<slug>-ch02-exam-<n>.md`, `<dir>/exams/<stem> — Exam <n>.md`. Schemes: same name with `.json` under the sibling `.exams/`. Snapshots: `.submitted.md` under `.exams/`.
- Paper statuses: `open` → `submitted` → `graded`, or `abandoned`.
- Budgets (MC × marks, short × marks, problems × marks, total): short 4×2, 2×4, 1×8 = 24; standard 6×2, 3×4, 2×8 = 40; long 8×2, 4×4, 3×10 = 62.
- Callout types: `success` full marks, `warning` partial, `failure` zero. Summary: `> [!summary] Result — <score>/<marks> (<pct>%)`.
- `shaky` only from `done`, when a unit's questions scored under 50% of their marks; never cleared by a score.
- Script status lines start with `🗒` (the mirror drops them).
- Docs follow the house style: simple technical English, short sentences. The README is a tutorial, not a changelog: no bug history, no defensive "never" sentences.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **A heading inside an answer.** A learner who writes `### Step 1` or `## Working` in a long answer expects it to stay part of the answer. Only `### Q<n>` and `## Part ` headings delimit questions. Pinned in Task 2.
2. **Checkbox variants.** Obsidian and hand-editing produce `- [x]`, `- [X]`, `* [x]`, and extra spaces. All of them count as a tick; the option is identified by its letter `a)`, not by its position or its text. Pinned in Task 2.
3. **An answer on the `**Answer:**` line itself** (`**Answer:** 0.3`). It is the answer, not a blank. Pinned in Task 2.
4. **Half marks.** The teacher awards `1.5`. Totals, percentages and callouts show `1.5`, never `1.50` or a rounded `2`. Pinned in Task 5.
5. **Names with spaces and an em dash** (`notes/Bayes rule.md` → `notes/exams/Bayes rule — Exam 1.md`) through every command and in wikilinks. Pinned in Task 3.

      2. set `status: submitted` and `submitted: <date>` in the paper and the scheme;

         - `MULTIPLE CHOICE: <score>/<marks>`, with one line per question, `Q1 2/2 (a)` or `Q2 0/2 (b; correct c)`;
         - per written question, a block headed `=== Q7 (4 marks, short, §2.3) ===` with `QUESTION:` (the paper's text between the heading and `**Answer:**`), `MODEL ANSWER:`, `POINTS:` (one `- [2] text` line each) and `ANSWER:` (verbatim, or `(blank)`);

         - `BLANK: Q3, Q9` when any.
