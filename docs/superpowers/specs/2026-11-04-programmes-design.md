# Programmes — design

Date: 2026-11-04. Status: agreed in conversation ("a programme over the book courses"); built the same day.

## Purpose

The learner revises for quant research assessments from five books at once: Blitzstein & Hwang (`bh`), Wasserman (`stats`), Strang (`strang`), the Green book (`gb`) and later Mosteller (`mosteller`). Studied as separate courses, the books are switched with `/course use` and nothing ties Strang §3.3 (projections) to Wasserman §13.2 (least squares). A **programme** is one course made of units from several book courses, grouped into topic modules. The books keep everything that belongs to a book (page map, figures, exercise ids, equation numbers, chapter notes, progress). The programme adds only order and grouping.

## Data

- `courses/<name>/.programme/programme.json`: `slug`, `title`, `goal`, and `modules`, each `{"title", "spec": ["bh:7.1-7.5", "strang:3.3"], "units": [["bh", "7.1"], …]}`. A member course is named by its directory under `courses/`, so the file holds no absolute paths.
- `courses/<name>/<name>.md`: the **programme note**. The top of it, down to `%% /programme index %%`, is the index, regenerated by every `programme.py` command: books, progress, and per module its units with status marks, each unit linked to its section heading in the book's chapter note once that heading exists. Below the end marker is lesson content: one `## Module n — <title>` heading per module with its `### Overview`, written by the mirror. Regeneration keeps everything below the marker byte for byte.
- `md-log-state/programme.json`: `{"programme": <dir>}`, the programme pointer.

## The current course while a programme runs

`book.py` rewrites `md-log-state/course.json` on every command, so a programme key in that file would be lost; the pointer is a separate file and `book.py` is unchanged. A programme is **current** when its pointer is set and the current course is one of its books (or it has none yet). So `book.py new` or `/course use pml1` leaves the programme without a further command, and `/course use bh` keeps it.

**The pointer is switched per unit.** `programme.py next` and `section` set `course.json` to the unit's book before printing it. Every `book.py` command a skill already runs (`done`, `exercise`, `figure`, `find`, `toc`), `/exercise`, `/exam <chapter>`, `/interview`, figures and section links then act on the right book with no `--course` and no change to those skills. Printing a `--course` value instead would need every skill to pass it, and a call that forgot it would write to the wrong book. `programme.py done` leaves the pointer on the finished unit's book, so `/exam <chapter>` after it is about that chapter.

## Commands (`hooks/programme.py`)

```
programme.py new <name> --title T [--goal G]
programme.py module "<title>" <course>:<spec> [<course>:<spec> | <spec> ...] [--at N]
programme.py move <n> <to> · remove <n> · set <title|goal> <value>
programme.py next · section <course>:<unit> · done [<course>:]<unit> [--status S]
programme.py status · list · use <name> · members · index · off
```

- `module` adds a module, or replaces the units of the module with that title. A spec is as in `book.py select`; a spec without a prefix belongs to the course named before it. Units keep the order of the specs (within one spec, book order). A unit may sit in one module only.
- Every change to the modules sets each member's `book.py` syllabus to its programme units plus the units it has already done or marked shaky, so the book's own index and status agree with the programme.
- `next` gives the first unit, in programme order, whose status in its book is `todo`. `done` records the unit in its book with the same rules as `book.py done`, then names the next unit of the programme. Its output is one of: the next unit in full (same note, go on); the next unit is in another note (checkpoint, `/course next`); the module is complete; the programme is complete. A line `CHAPTER … COMPLETE` and the `EXAM:` line follow when the book chapter has no unit left.
- With no programme current, `next`, `section`, `done`, `status` and `use` do what `book.py` does, so the course skill always calls `programme.py` for them.

## Teaching

- **Module start.** A module starts when the programme note has no `## Module n — <title>` heading for it. `next` then prints `MODULE START`, the heading, and the module's units with their books and pages. The teacher links the programme note (`--from-now --no-header`) and writes the heading and a `### Overview`: what the module covers, its units in order and why, how the books connect, a mermaid map, and the ready-or-probe line. On `ready`, the chapter note of the first unit is linked and the unit is taught.
- **A chapter first reached through a programme** opens with a short `### Overview` of two or three sentences that links to the module overview; no chapter-sized overview and no second choice. `next` prints `PROGRAMME CHAPTER START` when this applies.
- **Goal.** The programme's goal is printed as `PROGRAMME GOAL` and replaces the book's goal line.

## Out of scope; follow-ups

- The interview scope over a programme's books: `programme.py members` prints their directories for the `firm-interviews` branch to use as its default scope.
- `/exercise` and `/exam` act on the current book; for another book of the programme, `/course use <book>` first (the programme stays current).
- One unit in two modules; programmes of programmes.

## Testing

`tests/test_programme.py`, in a throwaway vault with two fake courses: syllabus sync (including done units kept); spec parsing, order, duplicate and unknown-course errors; `next` at a module start and after it, and the chapter-start line; the pointer switch; every `done` outcome and the exam line; `status`, `list`, `use` (programme, member, non-member, fall-through to `book.py`); `move`, `remove`; the index keeping the body below its marker and linking taught headings.
